# 06. Project Scope

## 주요 구현 과제

| 과제 | 구현 내용 | 결과 |
|:---|:---|:---:|
| 정보 분산 | 공시·중요 정보·참고자료·일정을 종목 중심으로 연결 | 완료 |
| 출처 혼재 | 공식 출처·2차 출처·참고자료와 검토 상태 구분 | 완료 |
| 반복 정보 | 통합 사건으로 연결해 중복 확인 감소 | 완료 |
| 변경 추적 | state fingerprint 기반 변경 브리핑 | 완료 |
| 사용자 확인 | Preview와 Final Confirm으로 반영 단계 분리 | 완료 |
| 데이터 신뢰성 | 미설정 Provider에 임의 값 생성 금지 | 완료 |
| 데이터 안전성 | 실제 투자 데이터와 검증 데이터 분리 | 완료 |

## 최종 구현 범위

- 분석 종목 등록·수정·상세 분석
- 거래 기록과 Position 계산
- 공식 출처·구독·참고자료 관리
- 자동 발견 후보의 검토·승격·제외
- 중요 정보 URL 등록과 중복 확인
- 공식 공시 등록과 통합 사건 연결
- 경제·기업 일정과 종목 연결
- 변경 기반 브리핑
- 위험 기준과 규칙 기반 종목 관리 방향
- 개인 설정과 시스템 연결 상태
- Scheduler·로그·DB revision 보호 구조
- Backend·Frontend·Browser 자동 회귀
- 실제 UI 13개 기능 시나리오 검증

## 설계상 제외 범위

- 자동 주문·자동매매
- 증권사 계좌 인증·연동
- 계좌 잔고 자동 동기화
- 실시간 전문 주식 차트
- 투자 수익 보장
- 자동 매수·매도 성공 확률
- 사용자의 확인 없이 생성되는 투자 명령
- 기사·유료 문서 전문 저장
- 공개 인터넷 서비스용 인증·HTTPS
- 카카오톡·모바일 Push

이 항목들은 미구현 잔여 기능이 아니라 Investment AI Radar가 **정보 검토와 의사결정 보조 도구**로 동작하도록 정의한 제품 경계입니다.

## 운영 범위

- 로컬 Web·API 실행
- SQLite + Alembic 기반 데이터 관리
- Windows Scheduler 연결 구조
- Provider·DB·자동화 상태 표시
- Provider 미연결 상태의 명시적 표시
- Secret과 실제 투자 데이터의 로컬 분리

외부 Provider, 이메일, 시장 일정과 외부 배포 환경은 연결 여부에 따라 달라지는 선택적 운영 구성으로 분리했습니다.
