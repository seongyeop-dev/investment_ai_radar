# 04. Data Flow

## 전체 데이터 흐름

```text
분석 종목·거래 기록
        ↓
공식 출처·공개 자료
        ↓
등록 전 확인 / 자동 발견 후보
        ↓
출처·중복·상태 검토
        ↓
Reference / Information Event / Economic Event
        ↓
Portfolio·통합 사건 연결
        ↓
변경 기반 Briefing / 관리 방향
        ↓
사용자 최종 판단
```

## 1. 사용자 입력

```text
분석 종목 등록
→ 거래 기록
→ 보유·관심 상태 관리
```

실제 증권계좌와 자동 동기화하지 않습니다.

## 2. 공개 정보 등록

```text
공식 URL 또는 공개 참고자료
→ 등록 전 확인
→ URL 정규화
→ 중복 검사
→ 출처·종목 연결 확인
→ 최종 등록
```

외부 기사 전문 전체를 저장하지 않습니다.

## 3. 자동 발견 후보

```text
출처 자동 확인
→ 검토 대기 후보
→ 발행일·출처 확인
→ 사용자 승인
→ 정식 참고자료 승격
또는
→ 검토 제외
```

검토 전 후보는 투자 판단 계산에서 격리합니다.

## 4. 사건 연결

```text
뉴스·중요 정보
공식 공시
참고자료
     ↓
Information Event / 통합 사건
     ↓
Portfolio 연결
     ↓
다음 확인 일정·관리 방향
```

## 5. 경제·기업 일정

```text
공식 일정 URL
→ 시각·출처 확인
→ 예상 영향 경로 입력
→ 종목 연결
→ 다음 확인 일정에 표시
```

## 6. 변경 기반 브리핑

```text
기간 내 Information Event
→ 중요도·상태 조건
→ 기존 state fingerprint와 비교
→ 변경 항목만 선별
→ Preview
→ 사용자 확인
→ Final Briefing 저장
```

## 7. 사용자 판단

```text
Dashboard / 종목 상세 / 브리핑
→ 근거와 미설정 데이터 확인
→ 규칙 기반 관리 방향 확인
→ 사용자가 최종 판단
→ 실제 주문은 외부 금융 앱에서 별도 수행
```

## 오류 처리 원칙

- 중복 자료: 기존 자료 반환 또는 등록 차단
- 상태 충돌: 구조화된 `409`
- 잘못된 입력: validation error
- Provider 실패: 기존 저장 데이터와 Portfolio 불변
- 늦은 검색 응답: 최신 요청 결과를 덮지 않도록 방지
